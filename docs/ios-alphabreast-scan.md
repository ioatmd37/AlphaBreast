# AlphaBreast Scan — สเปกแอป iOS (alpha)

เอกสารนี้เป็นสเปกเริ่มต้นสำหรับสร้างแอป iOS ที่สแกนลำตัวส่วนหน้าด้วย LiDAR แล้วส่งออกไฟล์ให้เว็บ
[augsizer](https://augsizer.pages.dev/#scan) นำไปจุดตำแหน่ง วัดระยะ และสร้างภาพผนังอก

สถานะ: ร่างแรก ยังไม่มีโค้ด iOS รายละเอียด API ของ Apple ในเอกสารนี้เขียนจากความรู้ทั่วไป
ต้องตรวจกับเอกสาร Apple ฉบับปัจจุบันก่อนลงมือ

---

## 1. เป้าหมาย

| ต้องได้ | ไม่ทำในรุ่น alpha |
|---|---|
| โมเดล 3 มิติของลำตัวส่วนหน้า มาตราส่วนจริง หยาบระดับ 5–10 mm | ผิวละเอียดระดับรูขุมขน |
| ตำแหน่ง landmark 9 จุด + จุดอ้างอิง | จำลองผลผ่าตัดในแอป |
| ไฟล์ส่งออกที่เว็บ augsizer เปิดได้ | บัญชีผู้ใช้ ระบบ cloud หรือซิงก์ |
| ใช้งานจบใน 2 นาทีต่อผู้ป่วย | เผยแพร่บน App Store สาธารณะ |

ผู้ใช้: ศัลยแพทย์หรือผู้ช่วยในห้องตรวจ ผู้ป่วยไม่ได้ถือเครื่องเอง

## 2. เหตุผลที่ต้องเป็นแอป native

เว็บเบราว์เซอร์บน iOS เข้าถึง LiDAR ไม่ได้ หน้าเว็บ alpha ปัจจุบันจึงรับได้เฉพาะไฟล์ที่ export
จากแอปสแกนของบุคคลที่สาม แอปนี้ทำให้ขั้นตอนสแกน จุดตำแหน่ง และส่งออกอยู่ในที่เดียว
และควบคุมได้ว่าข้อมูลไม่ออกนอกเครื่อง

## 3. อุปกรณ์และข้อกำหนด

- iPhone Pro หรือ iPad Pro ที่มี LiDAR (กล้องหลัง)
- iOS 17 ขึ้นไป (เพื่อให้เลือกใช้ Object Capture ได้ในภายหลัง)
- Swift + SwiftUI, ARKit, RealityKit, ModelIO
- แจกผ่าน TestFlight แบบ internal เท่านั้นในช่วง alpha

## 4. วิธีเก็บข้อมูล (เลือกหนึ่งทางสำหรับ alpha)

| ทางเลือก | วิธี | ข้อดี | ข้อเสีย |
|---|---|---|---|
| **A. ARKit scene reconstruction (แนะนำสำหรับ alpha)** | `ARWorldTrackingConfiguration` เปิด `sceneReconstruction = .mesh` แล้วรวม `ARMeshAnchor` | โค้ดน้อยที่สุด ได้ mesh มาตราส่วนจริงทันที | mesh หยาบ ออกแบบมาสำหรับห้อง ไม่ใช่ร่างกาย ต้องทดสอบว่าพอสำหรับรูปเต้าหรือไม่ |
| B. Depth fusion เอง | เก็บ `sceneDepth` ทีละเฟรม รวมเป็น point cloud แล้วสร้างผิว | ละเอียดกว่า A ควบคุมได้เต็มที่ | งานมาก ต้องเขียนขั้นรวมและสร้างผิวเอง |
| C. Object Capture | `ObjectCaptureSession` + `PhotogrammetrySession` บนเครื่อง | ผิวและ texture ดีที่สุด | ใช้เวลาประมวลผลนาน ผู้ป่วยต้องนิ่งนานกว่า และผิวลายน้อยอาจให้ผลไม่ดี |
| D. TrueDepth (กล้องหน้า) | `AVCaptureDepthDataOutput` | ละเอียดในระยะใกล้ | ระยะสั้น มองจอไม่เห็นขณะสแกน ครอบคลุมลำตัวยาก |

แผน: เริ่มที่ A เพื่อพิสูจน์ทั้งวงจร ถ้าความละเอียดไม่พอสำหรับรูปเต้า ให้ย้ายไป B โดยคงรูปแบบไฟล์ส่งออกเดิม

## 5. ขั้นตอนการใช้งาน

1. **ปลดล็อก** ด้วย Face ID หรือรหัสเครื่อง (ดูข้อ 9 เรื่องรหัส alpha)
2. **เตรียมผู้ป่วย** แอปแสดงแผนภาพตำแหน่ง marker และรายการตรวจก่อนสแกน
3. **สแกน** ผู้สแกนเดินโค้งจากด้านข้างหนึ่งไปอีกด้าน แอปแสดง mesh ซ้อนภาพสดและแถบบอกพื้นที่ที่ยังไม่ครอบคลุม
4. **ตรวจผล** หมุนดูโมเดล ถ้ามีรูหรือผิวขาดให้สแกนใหม่
5. **จุด landmark** แตะบนโมเดลตามลำดับ 9 จุด แก้ไขและย้อนกลับได้
6. **ดูค่าวัด** SN-N, base width, N-IMF ขณะพัก, ระยะ NAC ถึง NAC, intermammary distance
7. **ส่งออก** ไฟล์โมเดล + ไฟล์ landmark ผ่าน share sheet (AirDrop หรือ Files) แล้วลบออกจากแอป

## 6. โปรโตคอลการสแกน

**ท่าผู้ป่วย**
- ยืนตรง มือเท้าสะเอว กางศอกเล็กน้อยให้เห็นรักแร้
- กลั้นหายใจช่วงหายใจออกสุดขณะสแกน
- รวบผม ถอดเครื่องประดับ

**ผู้สแกน**
- ถือเครื่องห่างจากผู้ป่วย 40–60 cm
- เดินโค้งราว 180° จากด้านข้างหนึ่งไปอีกด้าน ระดับเครื่องอยู่ที่หน้าอก
- กวาดขึ้นลงเล็กน้อยให้เห็นใต้ราวนมและเหนือไหปลาร้า
- เป้าหมายเวลา 30–60 วินาที

**แสง**: สว่างสม่ำเสมอ ไม่มีแสงแดดตรง (แสงแดดรบกวน LiDAR)

## 7. Marker และ landmark

ใช้ marker แบบนูน เส้นผ่านศูนย์กลาง 8–10 mm ผิวด้าน เช่น แผ่น ECG electrode
เพราะ LiDAR หยาบเกินกว่าจะเห็นจุดสีแบน

### จุดวัด (ต้องจุดครบ ตามลำดับนี้)

| ลำดับ | key | ตำแหน่ง | แปะ marker |
|---|---|---|---|
| 1 | `sn` | Sternal notch | ใช่ |
| 2 | `nR` | NAC ขวา | ไม่ต้อง |
| 3 | `nL` | NAC ซ้าย | ไม่ต้อง |
| 4 | `imfR` | IMF ขวา จุดต่ำสุดของรอยพับใต้ NAC | ใช่ |
| 5 | `imfL` | IMF ซ้าย | ใช่ |
| 6 | `medR` | ขอบในเต้าขวา ที่ระดับ NAC | ใช่ |
| 7 | `latR` | ขอบนอกเต้าขวา ที่ระดับ NAC | ใช่ |
| 8 | `medL` | ขอบในเต้าซ้าย | ใช่ |
| 9 | `latL` | ขอบนอกเต้าซ้าย | ใช่ |

key ชุดนี้ตรงกับที่หน้าเว็บ alpha ใช้อยู่ (`src/components/ScanAlpha.tsx`) ห้ามเปลี่ยนชื่อโดยไม่แก้ทั้งสองฝั่ง

### จุดอ้างอิง (ไม่บังคับ แต่แนะนำ)

| key | ตำแหน่ง | ใช้ทำอะไร |
|---|---|---|
| `xiphoid` | ปลายล่างกระดูกอก | กำหนดแนวกลางลำตัวร่วมกับ `sn` |
| `acromionR`, `acromionL` | ปุ่มหัวไหล่ | ระดับไหล่ และจัดแนวโมเดล |
| `scaleA`, `scaleB` | marker คู่ห่างกัน 10.0 cm บนหน้าท้อง | ตรวจมาตราส่วน |

แอปควรเตือนเมื่อระยะ `scaleA`–`scaleB` ที่วัดได้ต่างจาก 10.0 cm เกิน 3 mm

## 8. รูปแบบไฟล์ส่งออก

ส่งออกสองไฟล์ ชื่อฐานเดียวกัน เช่น `scan-20261004-1530.obj` และ `scan-20261004-1530.json`

### 8.1 โมเดล

- รูปแบบ: `.obj` (ทางหลัก) หรือ `.ply` ทั้งสองแบบเว็บเปิดได้แล้ว ส่งออกด้วย ModelIO (`MDLAsset`)
- หน่วย: **เมตร** (เว็บเดาหน่วยจากขนาดโมเดล และเมตรคือค่าที่เดาถูก)
- แกน: Y ชี้ขึ้น, Z ชี้ออกจากหน้าอกผู้ป่วยไปด้านหน้า, จุดกำเนิดใกล้กลางลำตัว
- ไฟล์เดียว ไม่มี texture แยก (ถ้าต้องการสีให้ใช้ vertex color ใน `.ply`)
- ตัด mesh ให้เหลือเฉพาะลำตัว ตั้งแต่โคนคอถึงเอว ตัดพื้นหลังและแขนส่วนล่างออก
- ขนาดเป้าหมาย: ไม่เกิน 100,000 สามเหลี่ยม

### 8.2 Landmark (`.json`)

```json
{
  "schema": "alphabreast-scan/1",
  "capturedAt": "2026-10-04T15:30:00+07:00",
  "units": "m",
  "device": "iPhone 16 Pro",
  "method": "arkit-scene-reconstruction",
  "landmarks": {
    "sn":   [0.000, 0.200, 0.050],
    "nR":   [-0.080, 0.000, 0.085],
    "nL":   [0.080, 0.000, 0.085],
    "imfR": [-0.080, -0.060, 0.060],
    "imfL": [0.080, -0.060, 0.060],
    "medR": [-0.020, 0.000, 0.050],
    "latR": [-0.140, 0.000, 0.040],
    "medL": [0.020, 0.000, 0.050],
    "latL": [0.140, 0.000, 0.040]
  },
  "references": {
    "xiphoid": [0.000, -0.050, 0.052],
    "scaleA": [-0.050, -0.180, 0.050],
    "scaleB": [0.050, -0.180, 0.050]
  }
}
```

- พิกัดอยู่ในระบบเดียวกับไฟล์โมเดล
- **ห้ามใส่ข้อมูลระบุตัวผู้ป่วย** (ชื่อ, HN, วันเกิด) ในไฟล์ทั้งสอง
- ขวา–ซ้ายหมายถึงของผู้ป่วย ไม่ใช่ของผู้มอง

งานฝั่งเว็บที่ยังไม่ได้ทำ: ให้หน้า alpha รับไฟล์ `.json` นี้คู่กับโมเดล เพื่อข้ามขั้นจุด landmark ซ้ำ

## 9. ความเป็นส่วนตัวและความปลอดภัย

ข้อมูลที่แอปจัดการคือภาพ 3 มิติของร่างกายเปลือย ถือเป็นข้อมูลอ่อนไหวตาม PDPA

- ประมวลผลและเก็บในเครื่องเท่านั้น ไม่มีการเรียกเครือข่ายใด ๆ ในรุ่น alpha
- ไม่บันทึกลง Photos ไม่ซิงก์ iCloud (ตั้ง `isExcludedFromBackup` กับโฟลเดอร์งาน)
- เข้ารหัสไฟล์ด้วย Data Protection ระดับ `complete`
- ลบไฟล์อัตโนมัติหลังส่งออก หรือเมื่อเกิน 24 ชั่วโมง
- ปลดล็อกแอปด้วย Face ID / รหัสเครื่อง (`LocalAuthentication`) ทุกครั้งที่เปิด
- บังหน้าจอเมื่อแอปเข้า app switcher
- มีหน้าขอความยินยอมจากผู้ป่วยก่อนสแกนทุกครั้ง พร้อมบันทึกเวลาที่ยินยอม (ไม่บันทึกตัวตน)

**รหัส alpha**: ใช้รหัสเดียวกับหน้าเว็บ alpha แต่ไม่บันทึกรหัสไว้ในเอกสารนี้หรือใน repo
ในแอปให้เก็บเป็นค่า hash หรือใช้การจำกัดผู้ทดสอบของ TestFlight แทนการฝังรหัส
รหัสในแอปเป็นการล็อกแบบอ่อน ความปลอดภัยจริงมาจากการล็อกเครื่องและการไม่ส่งข้อมูลออก

## 10. โครงสร้างแอป

```
AlphaBreastScan/
  App/                 จุดเริ่ม, การปลดล็อก, การนำทาง
  Capture/             ARSession, การรวม mesh, แถบความครอบคลุม
  Processing/          ตัด mesh, จัดแกน, ลดจำนวนสามเหลี่ยม
  Landmarks/           การแตะจุดบนโมเดล, ลำดับจุด, ค่าวัด
  Export/              เขียน .obj/.ply และ .json, share sheet, การลบ
  Guide/               แผนภาพ marker, รายการตรวจ, ความยินยอม
```

หน้าจอ: ปลดล็อก → คู่มือและความยินยอม → สแกน → ตรวจผล → จุด landmark → ค่าวัดและส่งออก

## 11. แผนงาน

| ระยะ | ผลลัพธ์ | เกณฑ์ผ่าน |
|---|---|---|
| M0 | พิสูจน์แนวคิด: สแกนหุ่นลองเสื้อด้วยทางเลือก A แล้ว export `.obj` | เว็บ alpha เปิดไฟล์ได้ และขนาดโมเดลตรงกับของจริงภายใน 1 cm |
| M1 | ตัดลำตัว จัดแกน จุด landmark ในแอป export `.json` | ค่า SN-N และ base width จากแอปต่างจากสายวัดไม่เกิน 0.5 cm บนหุ่น |
| M2 | คู่มือ marker, ความยินยอม, การล็อกและการลบข้อมูล | ผ่านรายการตรวจข้อ 9 ทุกข้อ |
| M3 | ทดลองกับอาสาสมัคร 5–10 ราย เทียบกับการวัดทางคลินิก | รายงานความคลาดเคลื่อนเฉลี่ยและสูงสุดของแต่ละค่าวัด |
| M4 | ตัดสินใจ: คงทางเลือก A หรือย้ายไป B / C | ตัดสินจากผล M3 |

## 12. ความเสี่ยงและคำถามที่ยังไม่มีคำตอบ

- **ความละเอียดของทางเลือก A อาจไม่พอ** mesh ของ ARKit ออกแบบสำหรับพื้นผิวห้อง ต้องทดสอบใน M0 ก่อนลงทุนต่อ
- **การหายใจและการขยับตัว** ระหว่างสแกน 30–60 วินาทีทำให้ผิวซ้อนหรือเบลอ
- **N-IMF ที่ได้เป็นค่าขณะพัก** เครื่องคำนวณในเว็บใช้ค่าขณะดึงตึง จึงยังต้องวัดด้วยมือ
- **ระยะเป็นเส้นตรงระหว่างจุด** ไม่ใช่ระยะตามผิว ต้องตัดสินใจว่าจะเพิ่มการวัดตามผิวหรือไม่
- **ต้องขออนุมัติจริยธรรมการวิจัย** ก่อนทดลองกับอาสาสมัครหรือผู้ป่วย (M3)
- **สถานะเครื่องมือแพทย์**: ถ้าใช้ค่าวัดประกอบการตัดสินใจทางคลินิก อาจเข้าข่ายซอฟต์แวร์เครื่องมือแพทย์ ต้องปรึกษาผู้เชี่ยวชาญด้านกฎระเบียบ
- **App Store**: เนื้อหาภาพร่างกายและการใช้งานทางการแพทย์อาจมีเงื่อนไขการตรวจเพิ่ม ช่วง alpha ใช้ TestFlight internal จึงยังไม่กระทบ
- ใครเป็นผู้พัฒนา iOS และมีบัญชี Apple Developer แล้วหรือยัง
- ต้องการให้แอปรองรับ iPad ด้วยหรือเฉพาะ iPhone
